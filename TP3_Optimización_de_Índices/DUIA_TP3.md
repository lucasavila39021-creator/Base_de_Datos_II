# Declaración de Uso de IA (DUIA) - Trabajo Práctico 3

| Herramienta | Para qué se usó | Prompt/spec (resumen) | Se aceptó / se descartó por qué |
| :--- | :--- | :--- | :--- |
| **OpenCode** | Parte 1: Generación de script de carga masiva de datos (seed). | "Generá un script SQL para PostgreSQL que inserte 50.000 filas en producto, distribuidas en categorías, y 200.000 pedidos. Usá generate_series." | **Se aceptó con modificaciones.** Se detectó un problema de rendimiento con subconsultas `LATERAL` no correlacionadas y se corrigió usando indexado de arrays (`array_agg`) para garantizar la aleatoriedad por fila. |
| **Kiro / OpenCode** | Parte 2: Análisis de planes EXPLAIN ANALYZE y propuestas de índices. | "Analizá el siguiente plan de ejecución (Seq Scan) y proponé reescrituras o un CREATE INDEX para optimizar el filtro y el ordenamiento." | **Se aceptó.** Las propuestas de índices cubiertos se aplicaron porque atacaban directamente el cuello de botella del Seq Scan, lo cual se comprobó al medir la reducción drástica del tiempo real de ejecución. |
| **OpenCode** | Parte 3: Generación de explicación en lenguaje natural del plan de ejecución para auditoría. | "Explicá este plan de ejecución (Index Scan con Limit) nodo por nodo en lenguaje natural, actuando como un asistente." | **Se descartó parcialmente (auditado).** Se utilizó el texto generado para el ejercicio de lectura crítica, detectando que la IA confundía el costo estimado máximo (cost) con el tiempo en milisegundos, y las filas estimadas con las filas reales procesadas. |
| **OpenCode** | Parte 4: Generación de SQL a partir de especificación estricta. | "Genera una consulta SQL sobre Food Store que devuelva, para cada categoría vigente, la cantidad de productos, ordenado de mayor a menor." | **Se aceptó.** La consulta generada respetó las restricciones solicitadas y se verificó su exactitud matemática al cruzarla con una consulta alternativa usando la cláusula `EXCEPT`, devolviendo cero diferencias. |
